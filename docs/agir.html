Guide pratique · d'après le code de l'algorithme de X

Agir sur X.

Faire reculer les comptes que vous ne voulez plus voir, faire avancer les idées que vous défendez : voici ce qui marche vraiment, et ce qui se retourne contre vous. Une règle traverse tout : ce qui compte, c'est l'envie de réagir que donne un post, pas l'accumulation mécanique de clics.

D'où viennent ces conseils ? Ils résument notre analyse détaillée du code de X, faite par Claude Code, l'assistant de programmation d'Anthropic, et relue par plusieurs agents Claude indépendants. X n'a publié qu'une partie de son algorithme : quand un conseil repose sur une déduction, la page le dit.

Réduire la visibilité des comptes

À fairePourquoi
Ne jamais leur répondre, ne pas les citer, ne pas les retweeter, même pour critiquerUne réponse ou une citation a un poids de 5, contre 0,66 pour un like. Rien dans le code de classement ne distingue l'accord du désaccord : une réponse critique les fait monter.
Cliquer sur « pas intéressé »Un signal volontaire et clair, pris en compte dans le score, et dans le second tri de la page quand il est activé.
Bloquer plutôt que masquerDans les deux cas, le compte disparaît de votre fil et votre geste apprend au modèle que les gens comme vous n'aiment pas ce contenu. Mais le blocage fait plus : il cache aussi les reposts et citations de ses posts, et il compte quand X note ses réponses (voir ci-dessous).
Signaler seulement les vraies infractionsC'est le signal qui pèse le plus sur la réputation d'un compte. Certains classifieurs qui peuvent suspendre un compte semblent, d'après leur nom, s'appuyer sur les signalements. Une partie des calculs ne retient que les signalements jugés légitimes.

Pourquoi bloquer est plus efficace que masquer

C'est le point le plus important à comprendre, et le plus souvent mal compris. On lit partout que masquer serait plus fort que bloquer, parce que son poids est plus élevé (−58,8 contre −31,2). C'est une erreur de lecture : ces poids ne retirent pas de points au compte à chaque clic. X s'en sert pour deviner si vous allez masquer ou bloquer l'auteur d'un post avant de vous le montrer, et le relègue plus bas dans votre fil s'il pense que oui (commentaire de X dans son code). Une fois le compte masqué ou bloqué, ses posts disparaissent de votre fil : faire les deux n'ajoute presque rien.

En revanche, le blocage a deux effets que le masquage n'a pas :

  1. Il cache aussi les reposts et citations de ses posts

    Quand quelqu'un d'autre reposte ou cite un post d'un compte que vous bloquez, ce repost ou cette citation est aussi retiré de votre fil (filtre de X). Pour un compte masqué, ce filtre ne retire que ses propres posts : les reposts et citations de ses posts par d'autres restent visibles. Une règle qui cacherait ces citations existe bien dans le code (règle des citations), mais elle est désactivée par défaut : elle ne fait que mesurer ce qu'elle aurait caché (config.rs).

  2. Les blocages reçus comptent dans la notation de ses réponses

    Sous un post, il peut y avoir des centaines de réponses. X les fait noter par son IA, Grok, pour repérer le spam et décider lesquelles mettre en avant. Parmi les informations données à Grok sur l'auteur d'une réponse figure le nombre de blocages « légitimes » qu'il a reçus dans les dernières 24 heures (grox/core/lm/thread.py).

    La note de Grok sert ensuite à classer la réponse. Une note de 0 colle en plus l'étiquette RiskyHighVizReply (« réponse à risque ») sur la réponse ; les comptes très influents et les comptes certifiés gris en sont exemptés (task_write.py). Concrètement : un compte bloqué par beaucoup de monde dans la même journée risque de voir ses réponses moins bien classées, donc moins visibles sous les posts où il intervient. Le masquage n'apparaît nulle part dans ce mécanisme.

Ce qu'on ne sait pas, car ce n'est pas dans le code publié : ce qui rend un blocage « légitime » (des blocages automatiques en masse ne comptent peut-être pas), quel poids Grok donne à ce chiffre parmi ses autres informations, et comment la note est ensuite utilisée pour afficher les réponses. Le mécanisme est détaillé dans l'analyse complète.

Rappel : ces gestes réduisent surtout la portée d'un compte chez les gens qui vous ressemblent, via les recommandations. Son propre public est à peine touché. Le détail et les liens vers le code sont dans l'analyse complète.

Augmenter la visibilité de vos idées

Comment lire ce tableau ? Chaque fois que quelqu'un ouvre son fil, X essaie de deviner comment cette personne va réagir à chaque post. Va-t-elle le partager ? Y répondre ? Le liker ? Plus un post a de chances de provoquer chez elle les réactions du haut du tableau, plus il est placé haut dans son fil.

Exemple : si X pense que Julie a de bonnes chances de partager votre post par lien, ce post monte beaucoup dans le fil de Julie. Si X pense qu'elle va seulement le liker, il monte peu. Ce qui compte, ce n'est donc pas de cliquer beaucoup vous-même, c'est l'envie de réagir que votre post donne à ceux qui le voient.

Ce qu'on peut en déduire

  1. Publier des posts originaux

    Des posts qui donnent envie de répondre, de citer et de partager : questions, informations, vidéos. Ce sont les réactions qui pèsent le plus.

  2. Se suivre mutuellement

    Entre personnes qui partagent les mêmes idées : X donne un bonus aux posts originaux d'un compte quand il les classe pour ses abonnés mutuels.

  3. Citer plutôt que retweeter

    Une citation crée un nouveau post à vous, qui contient le post d'origine. Contrairement à un retweet, elle peut recevoir le bonus mutuel de +15 chez les gens avec qui vous vous suivez : le code n'exclut du bonus que les réponses et les retweets (value_model.rs).

    Attention : une citation sans texte est comptée comme un simple retweet. Si vous cliquez sur « Citer » sans rien écrire, X publie un repost, sans bonus. Pour que la citation compte, il faut écrire un commentaire.

  4. Retweeter plutôt que liker

    Un retweet fait apparaître le post chez vos propres abonnés ; un like ne le diffuse pas, il sert surtout à dire au modèle ce qui vous plaît. Pour faire circuler un post, le like seul ne suffit pas.

  5. Réagir vraiment

    Répondre, partager, prendre le temps de lire : ça apprend au modèle que les gens comme vous aiment ce contenu, ce qui l'aide à le leur montrer.

Une limite : le code publié ne montre pas si le nombre total de réactions d'un post l'aide à remonter chez tout le monde. Il montre seulement que chaque lecteur se voit montrer ce à quoi il est susceptible de réagir.

Ce qu'il ne faut surtout pas faire

Le service anti-abus de X a des étiquettes dédiées au spam et aux campagnes. La plupart font coller SpamHighRecall sur le post, ce qui le retire des recommandations. Certaines mènent à la suspension du compte (enforcement_post.yaml, enforcement_user.yaml). Ce qui déclenche ces étiquettes n'est pas publié : les conseils ci-dessous se déduisent de leur nom.

  • Campagnes (anchor_campaign) : ne pas poster tous le même texte au même moment.
  • Réponses en rafale (fast_reply_spam) : ne pas inonder les réponses d'un post.
  • Réponses copiées-collées : Grok reçoit l'information « Reply Was Pasted » quand il note une réponse (thread.py). Chacun écrit avec ses propres mots.
  • Contenu généré par IA à la chaîne (llm_slop) : le post reçoit l'étiquette RiskyHighVizReply, le compte SpamHighRecall.
  • Faux comptes, bots, signalements de masse infondés : le code suspend les comptes repérés comme bots de spam pour « manipulation de la plateforme ». Les signalements abusifs sont aussi interdits par les règles de X.

En une phrase

Des posts originaux qui donnent envie de répondre et de partager, des gens qui se suivent entre eux et citent avec un commentaire plutôt que de retweeter ou liker, et un silence total face aux comptes adverses : « pas intéressé », bloquer plutôt que masquer, et ne jamais interagir avec eux.
